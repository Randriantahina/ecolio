# CI: what runs and what must pass

Workflows live in `.github/workflows/`. They run on every push and pull request to `main` and `dev`, filtered by path so a backend change doesn't rebuild the frontend.

| Workflow | Triggers on | Gates (all must pass) |
|----------|-------------|-----------------------|
| `backend.yml` | `backend/**` | `pint --test`, `pest --coverage` (PHP 8.5, in-memory SQLite) |
| `frontend.yml` | `frontend/**` | `pnpm lint`, `pnpm format:check`, `pnpm typecheck`, `pnpm test:coverage`, `pnpm build` |

## Rules
- **Run the same gates locally before every commit** (see `00-workflow-tdd.md`). CI failing on something that passes locally means the environments drifted: fix the drift, don't retry blindly.
- Never merge `dev → main` with a red or missing CI run.
- Never weaken a gate to get green (skipping tests, lowering coverage, disabling a lint rule, `--no-verify`). Fix the cause; if a rule is wrong, change it in its own `chore(ci)`/`chore(frontend)` commit and say why.
- Versions are single-sourced so CI equals local: pnpm from `packageManager` in `frontend/package.json`, Node from `.mise.toml`, PHP 8.5, lockfiles committed and installed with `--frozen-lockfile` / `composer install`.
- Adding a new check (e.g. Playwright e2e, PHPStan/Larastan, a coverage floor, a tenant-isolation suite) = update the workflow **and** the table above in the same commit. Playwright e2e joins CI once the first journey exists; coverage floors are introduced once there is code to measure.
- Secrets never go in workflow files; use GitHub repository secrets. Actions are pinned to a major version.
- Deployment is out of scope for now; add it as a separate workflow triggered from `main` when hosting is chosen.

## When CI is red
Read the failing log first, reproduce locally, fix with a test, commit `fix(ci): ...` or the proper scope. Report to the user what failed and why.
